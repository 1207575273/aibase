# init-project:项目初始化

模板源码在本 skill 的 `assets/template.tar.gz`(`git archive` 打出,不含 .git 与被忽略的文件,包头记录模板提交号),
**不联网、不 git clone**:解包后在本地 `git init` 一个全新的独立仓库,没有远端、没有模板的提交历史,
业务代码不可能被推到公共的模板仓库。脚本会在首次提交后校验"没有任何远端",有就中止。
只依赖 Node 与 git(gzip 用 node:zlib,tar 用纯 Node 解包),沙箱里没有 tar 也能用。

模板更新后,在模板仓库提交,再运行 `node scripts/pack.mjs` 重新生成源码包并提交(只打已提交的内容,不含 `.claude/`)。

所有改动由 `scripts/init.mjs` 完成。你只负责:问清信息、执行脚本、读懂失败原因、交付。

## 第 1 步:探测端口

```bash
node "${CLAUDE_SKILL_DIR}/scripts/init.mjs" --check-ports
```

拿到可用端口段,作为第 2 步的推荐值。它会跳过本机正在监听的段,也会跳过 `projects.json` 里已分配的段
(项目没启动时端口看起来是空的,只靠探测会重复分配)。

## 第 2 步:一次问完

询问用户,**一次问完,不要逐条追问**。端口段给出第 1 步的推荐值让用户确认。

| 信息 | 参数 | 是否必填 | 说明 |
|---|---|---|---|
| 项目名 | `--name` | 必填 | 小写字母、数字、单个连字符,如 `order-system`。库名和 schema 自动转成下划线:`order_system_dev` |
| 显示名 | `--title` | 选填 | 页面标题,默认等于项目名 |
| 目标目录 | `--dir` | 必填 | 绝对路径,必须不存在或为空 |
| 端口段 | `--segment` | 必填 | 推荐第 1 步的第一个可用段。如 72 表示后端 7201、前端 7202、本机库 7203、测试入口 7204、e2e 8201 |
| 开发库 | `--dev-db-url` / `--dev-db-embedded` / `--dev-db-local` | **必填,三选一** | **优先容器外现成的 PG**,见下方「开发库怎么选」 |
| 测试库 | `--test-db-url` | 选填,**要提示** | 填了写入 `deploy/.env.test`,只保存不连接 |
| 生产库 | `--prod-db-url` | 选填,**要提示** | 填了写入 `deploy/.env.prod`,只保存不连接 |
| 初始管理员密码 | `--admin-password` | 选填 | 默认 `admin12345`,上线前必须改 |

### 开发库怎么选(按优先级,必须先问第 1 种)

| 优先级 | 参数 | 适用 | 说明 |
|---|---|---|---|
| 1(**优先建议**) | `--dev-db-url "<连接串>"` | 有容器外的 PG(公司开发库、本机 PG 等) | 不带 `?schema=`。数据不随沙箱走,团队可共用,最接近测试 / 生产 |
| 2(兜底) | `--dev-db-embedded` | 用户**明确说没有**外部 PG,且不能跑 docker(如沙箱) | 在项目 `.devdb/` 起嵌入式 PG 17.x(npm 包 embedded-postgres,首次下载约 60MB);只给本项目用,占沙箱资源;重启后要先 `pnpm db up` |
| 3 | `--dev-db-local` | 能跑 docker 的本机 | 沙箱里不可用 |

- **先问用户要容器外 PG 的连接串**。用户说没有时,讲清第 2 种的代价(数据只在本项目目录、要手动 `pnpm db up`、占资源),**用户同意后**才用 `--dev-db-embedded`
- **不许自己挑第 2 种**,也**不许用 skill 以外的方式自己起数据库**(自装 embedded-postgres、apt 装 postgresql、下载 PG 二进制等)

测试库和生产库在初始化阶段**不是必填**,但必须问到:告诉用户"现在不填也可以,部署前需要补上"。
用户跳过时,脚本结束会打印补配的方法,交付时原样转告。

## 第 3 步:执行

```bash
node "${CLAUDE_SKILL_DIR}/scripts/init.mjs" \
  --name <项目名> --title <显示名> --dir <目标目录> --segment <端口段> \
  --dev-db-url "<开发库连接串>" \
  [--test-db-url "<测试库连接串>"] [--prod-db-url "<生产库连接串>"] [--admin-password "<初始管理员密码>"]
```

- 每个参数都**取自第 2 步用户的回答**,不要自己编值,也不要沿用文档里的示例
- 方括号里的是选填项:用户没给就**不传**,脚本会用默认值或在结束时提示补配
- 开发库用户选了嵌入式库时,把 `--dev-db-url` 换成 `--dev-db-embedded`;选了本机 docker 时换成 `--dev-db-local`

脚本步骤:环境预检 -> 解包模板 -> 改名与端口 -> 首次提交 -> 写入目标目录 -> 环境配置 -> 装依赖 ->
(本机库)-> 建表与种子 -> `pnpm verify`。每步打印 `[PASS]`,失败打印 `[FAIL]` 并以退出码 1 中止。
全量验证需要几分钟,不要中途打断。

## 决策登记

每次初始化的决策写进 `projects.json`(与 `config.mjs` 同目录,只在本机):项目名、显示名、目录、端口、
开发 / 测试 / 生产 schema、数据库地址(**不含账号密码**)、模板版本、状态。
状态:`initializing`(写入目录后,未完成)/ `ready`(验证通过)/ `unverified`(用了 --skip-verify)。
名称、目录、端口段与已登记的重复会被拒绝。查看已有项目:

```bash
node "${CLAUDE_SKILL_DIR}/scripts/init.mjs" --list
```

## 第 4 步:交付

10 行以内,照抄脚本最后的汇总,不要自己拼地址:目录、`cd <目录> && pnpm dev`、前后端地址、账号、开发库 schema;
测试库 / 生产库未配置的提醒原样转告。让用户先读新项目的 `CLAUDE.md`,加业务模块看 `docs/add-module.md`。

## 失败处理

**先读 `[FAIL]` 后面那句,不要原样重跑。**

| 失败在 | 目标目录状态 | 怎么办 |
|---|---|---|
| 预检 / 解包模板 / 改名 / 首次提交 | 不存在(在临时目录里做) | 修掉原因直接重跑 |
| 写入目标目录之后(装依赖 / 建表 / 验证) | 代码完整,只是未验证 | 进目录续跑:`pnpm install && pnpm db deploy && pnpm db seed && pnpm verify` |

| 报错 | 处理 |
|---|---|
| 缺少模板源码包 | skill 上传不完整,**停下**交给用户:在模板仓库运行 `scripts/pack.mjs` 后重新上传 skill |
| 端口段被占用 | 重新 `--check-ports`,换一个段 |
| 改名不完整,模板可能已变更 | **停下**,把报错原样交给用户。绝不改脚本正则绕过 |
| `--dev-db-local` 需要 docker | 沙箱里没有 docker,先问用户要容器外 PG 的连接串(`--dev-db-url`);没有再征得同意用 `--dev-db-embedded` |
| 用户没有可用的开发库 | **停下问用户**,按「开发库怎么选」的顺序给选项,不要自己起库 |
| 嵌入式库启动失败 | 看 `.devdb/postgres.log`;端口被占就换段重新初始化。不要改用别的方式起库 |
| 环境文件没有被 git 忽略 | **停下**,不要提交,交给用户 |

- 允许在本 skill 的 `tmp/` 目录写临时脚本与文件处理脚本报错,密码只走环境变量;不能借此绕过上面的约束
- 问题解决后在 `LESSONS.md` 追加:**现象 -> 原因 -> 处理**

## 绝不做

- 不删除、不清空用户已有的目录
- 验证没通过不按成功交付;用了 `--skip-verify` 必须说明"尚未验证"
- 不运行 `pnpm dev`(常驻进程,会挂住会话),只告诉用户命令
- 不把测试库 / 生产库连接串写进会提交的文件
- 不给新项目添加模板仓库作为远端,不向模板仓库推送任何代码;新项目的远端由用户自己决定
