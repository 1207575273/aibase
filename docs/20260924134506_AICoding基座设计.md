# AICoding 基座设计

> 项目原名 keel,2026-10-07 改名为 aibase,下文统一用新名字。

> 状态:v3,内核已落地(见第 9 节) | 日期:2026-09-24
> 一句话:**aibase 就是基座**。一套目录从 share 这么简单的项目长到 teamspace 这么复杂的项目,结构不变,只是数量变多。

---

## 1. 要解决什么

人在 TeamSpace 里提需求,AI 在项目沙箱里写代码。基座把技术栈、分层、数据库、测试、运行、交付**一次定死**,AI 只写业务。

**Done 定义**:

1. 沙箱里一条命令从空目录得到能跑、测试全绿的项目;
2. AI 按需求加一个业务模块,自带测试,门禁全绿;
3. 一条命令把服务起起来,人能在浏览器里看到;
4. 一条命令产出交付包,目标机一条命令装起来;
5. 本地开发与沙箱用同一个模板。

## 2. 从三个真实项目得出的判断

| | share | aibase | teamspace |
|---|---|---|---|
| 规模(server 源码行数) | 约 3k | 约 7k | 约 92k |
| 业务域 | 1 个 | 1 个(identity) | 12 个 |
| server 内部 | 按层平铺 | 原按层,**已改为按模块** | 按模块,模块内四层 |
| 横切基础设施 | platform/ + lib/ | **已收成 platform/ + lib/** | platform/(12 项) |
| 已沉淀的内容 | 日志、HMAC、双端口 | 认证、RBAC、行级权限、真库测试、容器部署 | 出站箱、调度、WS、沙箱 |

- 一级目录:前后端各占一个,共享库统一进 `packages/`(teamspace、share 与主流 monorepo 的做法),以后多一个共享库一级目录数不变;
- server 内部按模块组织(取 teamspace):只有 1 个模块时只多一层目录,长到十几个模块也不用搬家;
- 契约单独成包(`packages/contracts`):GitHub 调研两派做法中,Hono RPC / tRPC 式的"前端只从后端取类型"满足不了
  aibase 的运行时共享需求(权限码常量、表单复用 zod),独立契约包边界最清楚。

## 3. 一级目录与一级文件

```
server/      后端(Hono + Prisma)
web/         前端(Vite + React)
packages/    共享包,目前只有 contracts
e2e/         端到端测试(以后换 Playwright)
deploy/      交付物:Dockerfile、nginx、compose、启动脚本
scripts/     开发期命令的实现(.mjs)
docs/        项目开发文档
.claude/     settings / skills(随代码演进的流程)
```

判断规则:**会进交付包的放 deploy,开发期执行的放 scripts;教 AI 干活的流程放 .claude/skills,项目自己的设计决策放 docs。**

一级文件:`package.json`(命令契约)、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`tsconfig.base.json`、
`eslint.config.mjs`、`.env.example`、`.npmrc`、`.gitignore`、`.dockerignore`、`.editorconfig`、`.nvmrc`、`CLAUDE.md`、`README.md`。

已移出根目录:`prisma.config.ts` -> `server/`,`contracts/` -> `packages/contracts/`。

## 4. server 内部结构

```
server/
  prisma.config.ts   所有 prisma 命令带 --config server/prisma.config.ts
  prisma/            schema.prisma、migrations/、seed.ts
  src/
    main.ts          进程入口,不随业务增长
    composition/     装配:context / modules / repos(仓储清单)/ app(路由总装 + 全站护栏测试)
    platform/        横切基础设施:config / db / logger / http(错误出口、校验、requirePermission)
    lib/             纯类型与纯函数:app-error / clock / page / actor / unit-of-work 端口
    modules/
      identity/      登录 / 用户 / 角色,也是加模块的抄写样板
        domain/ application/ infra/ interfaces/http/
  tests/helpers/     测试夹具(每个测试文件一个临时 schema)
```

一个业务模块 = `packages/contracts/src/<模块>.ts` + `server/src/modules/<模块>/` + `web/src/features/<模块>/`。

依赖边界(eslint,已用 17 条注入探针验证):

| 规则 | 内容 |
|---|---|
| R0 | lib 只依赖 lib;platform 不依赖业务模块与 composition |
| R1 | domain 只依赖 lib 与 domain |
| R1b | application 不依赖 infra / interfaces / platform / composition |
| R2 | 跨模块只准 import 对方的 domain |
| R3 | 只有 interfaces 与 platform/http 能 import 契约 |
| R4 | 只有 platform/config 能读 process.env |
| R5 | 前端业务层不直接 import axios |

UnitOfWork 拆成三处,消除反向依赖:`lib` 放泛型端口 `UnitOfWork<R>`,`platform/db` 放泛型 Prisma 实现
(`buildRepos` 由调用方传入),全量仓储清单只在 `composition/repos.ts`;每个 service 在 deps 里声明自己事务里要用的仓储。

## 5. 数据库:共享 PG,每项目一个 schema

`DATABASE_URL`(公共实例)+ `DATABASE_SCHEMA`(本项目 schema,不设即 public)。迁移与运行时读同一个变量。

| 位置 | 做法 |
|---|---|
| platform/config | `DATABASE_SCHEMA` 白名单校验(小写标识符,空值拒绝启动) |
| platform/db | adapter 的 `schema` 选项 + 连接级 `search_path`(两处都设,否则裸 SQL 落到 public) |
| prisma.config.ts | `DATABASE_SCHEMA` 拼成连接串 `?schema=`,`_prisma_migrations` 也落进该 schema |
| 测试隔离 | 每个测试文件一个临时 schema,重放迁移 SQL,用完 `DROP SCHEMA ... CASCADE`;不需要 CREATEDB |
| e2e | 同库独立 schema,走的正是沙箱上线路径 |
| 门禁 | 迁移 SQL 出现写死的 `"public".` 即测试失败 |
| 硬闸 | `pnpm db migrate` / `pnpm db reset` 只许连本机库(`scripts/db.mjs`) |

建议平台为每个项目建独立 PG 角色,只拥有自己的 schema(PG 只允许删自己拥有的 schema)。

## 6. 测试

| 层 | 位置 | 连什么 |
|---|---|---|
| lib / domain 纯函数 | 源码旁 `*.test.ts` | 无 |
| application / 路由 | 源码旁 `*.test.ts` | 真 PG(临时 schema) |
| 端到端 | `e2e/` | 起真进程,独立 schema |

"生成测试"靠两件事:加模块手册规定没有测试不算完成;全站遍历护栏(匿名全 401、零权限全 403)自动覆盖新路由。

Playwright 与浏览器由沙箱镜像预装、版本钉死,禁止 CC 现场安装(技能写明 + settings.json 硬拦)。

---

## 7. 交付:tar 包 + docker compose v2

沙箱里不构建镜像。`pnpm package` 产出 tar 包(compose.yaml、可选 compose.db.yaml、Dockerfile、nginx、源码、
lock、.env.example、install.sh、VERSION),目标机 `install.sh` 检查 compose v2 与必填项后 `up -d --build --wait` 并探活。

## 8. 人决定的事

| 时机 | 问什么 |
|---|---|
| 初始化 | 项目名、系统标题 |
| 加模块 | 实体中文名、字段清单、枚举值、是否需要行级数据权限、权限码粒度 |
| 不可逆操作 | 删数据、改已有迁移、改公共契约 |

沙箱里用平台的 CCQ 协议提问,本地用 AskUserQuestion。
